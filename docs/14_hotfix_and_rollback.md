# Задание 14. Обновление, hotfix и откат

## Хронология (заполняется по ходу работы)
| Версия | versionCode | Что в ней | Дата/время | Статус |
|---|---|---|---|---|
| 1.0.0 | 10000 | базовый релиз | | выпущена |
| 1.1.0 | 10100 | исправление дубликатов + сортировка А–Я + in-app updates | | выпущена |
| 1.2.0 | 10200 | «Поделиться» (с дефектом) | T0 | rollout остановлен |
| 1.2.1 | 10201 | hotfix | T3 | выпущена |

## 1.1.0 (исправление + новая функция)
`version.properties` → `VERSION_NAME=1.1.0`, коммит, `scripts/tag-release.sh` → CI соберёт и опубликует в internal →
подтверждение в GitHub Environments → production 1%. Тексты «Что нового» — в `app/src/main/play/release-notes/`.

## Симуляция неудачного 1.2.0
Создайте ветку `release/1.2.0`, `VERSION_NAME=1.2.0` и внесите умышленный дефект в `TaskList.toShareText()`:
```kotlin
// БЫЛО: _items.mapIndexed { i, s -> "${i + 1}. $s" }.joinToString("\n")
// СТАЛО (баг 1.2.0): падает при пустом списке
fun toShareText(): String = "1. ${_items[0]}" + _items.drop(1).mapIndexed { i, s -> "\n${i + 2}. $s" }.joinToString("")
```
Нажатие «Поделиться» при пустом списке → `IndexOutOfBoundsException` (виден в Crashlytics).
Выпустите 1.2.0 на 1–10% (staged rollout) и дайте crash-free users упасть.

## Реакция (фиксируйте время)
| Метка | Событие | Время |
|---|---|---|
| T0 | релиз 1.2.0 начат (rollout 1%) | |
| T1 | алерт Crashlytics / первый отзыв — **обнаружение** | |
| T2 | Production → **Halt rollout** — **остановка** | |
| T3 | выпущен 1.2.1 (VERSION_NAME=1.2.1 → versionCode 10201 > 10200), rollout 100% | |
| T4 | crash-free users вернулся к норме | |

Время обнаружения = T1 − T0, время остановки = T2 − T1, **время восстановления (MTTR) = T3 − T1** (или T4 − T1).
Именно поэтому hotfix обязан иметь более высокий versionCode: Play не принимает тот же или меньший код, а у пользователей
с 1.2.0 обновление до 1.2.1 должно считаться обновлением.

Параллельно, **до** выхода hotfix, выключите дефектную функцию через Remote Config: параметр `share_tasks = false` →
Publish changes — кнопка «Поделиться» исчезнет у всех, у кого уже установлена 1.2.0 (см. `FeatureFlags.kt`).

## Почему нельзя «откатить» версию на уровне пользователя
- Магазин принимает только **возрастающий** versionCode; публикация старого AAB под прежним номером невозможна.
- Установленное у пользователя приложение нельзя заменить старой версией: Android блокирует даунгрейд (versionCode ниже
  установленного), Google Play не умеет «откатывать» пользователей.
- Данные пользователя могли быть перенесены миграцией базы в новый формат; старый код не прочтёт их.
- «Halt rollout» лишь останавливает дальнейшую раздачу — тем, кто уже обновился, версия остаётся.

## Чем заменяют откат
1. **Halt rollout** + быстрый **hotfix** с большим versionCode (содержит код предыдущей версии с исправлением).
2. **Remote Config / feature flags** — выключаем дефектную функцию без нового релиза (`share_tasks=false`).
3. **Принудительное/приоритетное обновление** (in-app updates, `UpdatePolicy`): на hotfix ставим приоритет 5 через
   Play Developer API (`inAppUpdatePriority`) либо поднимаем `min_supported_version_code` в Remote Config до 10201 —
   приложение 1.2.0 покажет immediate-update экран.
4. **Серверная совместимость**: API должен переживать клиентов старых версий; bad-клиентов можно отсечь заголовком версии.
